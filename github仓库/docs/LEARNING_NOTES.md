# 学习笔记：从设计理念到可执行提示词

## 核心问题

AI 可以生成可运行的前端代码，却仍可能做出平庸的界面。问题通常不只是模型能力，而是任务定义太宽泛、默认方案过强、缺乏人类审美选择，以及没有基于真实渲染结果的验证。

## 设计理念转化为工程动作

### 1. 用外部随机种子打破默认路径

**理念**：让模型接触一个非默认的创意起点。

**工程动作**：使用随机字符串、主题卡片或限制条件作为灵感源；要求模型解释它如何映射到布局、节奏、字体、材质或交互；不把随机字符串展示在产品界面；保留 seed 和方案说明以便复现。

**失败模式**：随机只是表面装饰；方案与产品目标无关。

### 2. 用具体意象而不是空泛形容词

“高级、现代、漂亮”不可直接验收。把它们改写成具体选择：用户首先看见什么？页面的信息密度和阅读节奏如何？字体、颜色、留白和边界如何服务任务？哪些常见套路应该避免，为什么？用户完成主要任务需要几步？

### 3. 让人类参与设计方向选择

AI 负责扩展选项，人类负责品味判断。候选方案必须在结构、信息组织、视觉隐喻或交互模型上有明显区别，而不只是换色。

### 4. 评审真实渲染，而不是只读源码

至少检查桌面端首屏、移动端关键视口、主要交互状态、溢出/遮挡/断行与视觉层级、真实素材的裁切和融合。

### 5. 独立评审，减少自我辩护

评审上下文尽量只接收设计 brief、截图、目标视口和明确的评审标准。不要默认给它实现者的解释或自评分数。评审应区分客观故障与审美判断，并提供可定位的证据。

### 6. 先做减法，再加特效

每个可见元素都应回答：它支持什么用户目标？它提供什么信息或反馈？删除后会造成什么损失？渐变、3D、视频、动效不是禁忌，但必须有明确价值，并考虑性能、可访问性和维护成本。

## 从理念编译为提示词：六个字段

1. **目标**：最终要改变什么？
2. **上下文**：产品、用户、现有代码、品牌和限制是什么？
3. **动作**：模型应该按什么顺序做什么？
4. **产物**：必须输出哪些文件、截图或报告？
5. **验收**：如何判断完成？
6. **停止条件**：何时不再继续迭代，何时应询问用户？

## 重要原则

- 不把“AI 味”定义为某个固定视觉风格；应定义为缺乏产品依据、模板化、无理由的视觉选择。
- 不机械禁止渐变、圆角或卡片；要求每个选择有与任务相关的理由。
- 设计评分只用于辅助排序，不能替代人类判断和实际任务测试。
- 每轮只解决最重要的问题，避免无限修改。
