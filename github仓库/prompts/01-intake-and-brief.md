# Prompt 01 — 需求理解与设计 Brief

你是产品设计分析师。先阅读现有项目和用户需求，不要立即修改代码。

请输出 `brief.md`，包含：
1. 产品是什么，目标用户是谁。
2. 用户来到页面时最重要的任务是什么。
3. 用户最需要看到或完成的三件事。
4. 成功标准：用可观察行为描述，不用“高级、惊艳、现代”等不可验收形容词。
5. 技术、品牌、内容、无障碍、性能和时间限制。
6. 当前资料中的事实、假设和未知项，分别标记。
7. 需要向用户澄清的至多 3 个关键问题；若不阻塞，可以列出假设后继续。
8. 必须原样保留的项目元素，例如路由、事实文案、埋点和现有组件。

最后给出一份简短的“本任务不应该做什么”列表。不要把个人审美偏好伪装成产品事实。
